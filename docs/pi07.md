# pi0.7 paper-based implementation

This branch implements the disclosed pi0.7 VLA mechanisms in `src/openpi/pi07`, using actual Hugging Face Gemma 3/SigLIP modules, a continuous action expert, FAST supervision, temporal visual memory, and an asynchronous runtime. It includes an offline training/checkpoint smoke test. It does **not** contain Physical Intelligence's trained pi0.7 weights, private training mixture, or reproduced robot results.

The source specification is the supplied *π0.7: a Steerable Generalist Robotic Foundation Model with Emergent Capabilities* (`pi07.pdf`, [paper project page](https://pi.website/pi07)). Page numbers below refer to that PDF. The pre-existing `pi07_context_aloha` configuration remains a **pi0.5 model with textual metadata conditioning**; use the separate entry points below for the new implementation.

## Implemented mechanisms and evidence boundaries

| Paper specification | Implementation | Scope and explicit choices |
| --- | --- | --- |
| Gemma 3 4B VLM, including its vision encoder; pp. 3–4, 6 | `backbone.Gemma3Backbone` loads `Gemma3ForConditionalGeneration`; shares the native embedding/LM head and returns actual per-layer K/V | Full-scale weights must be supplied locally. Tests use small configurations of the real architecture. |
| MEM visual history, up to four cameras, six frames, 448×448 inputs; p. 6 | Parameter-sharing temporal attention in every fourth vision layer, current-frame readout, fixed-size spatial pooling | Spatial/temporal attention fusion and fixed time encoding are stated implementation choices; the unpublished MEM implementation is not recovered. Six slots include the current frame. |
| Projected continuous state history; p. 6 | Linear state projection, one token per history slot, shared validity with image history | State normalization and embodiment coordinate layouts are supplied by the dataset owner. |
| Block-causal context; p. 6 and Fig. 19, p. 22 | Bidirectional observations/states → causal text → bidirectional goals; FAST output is a separate causal branch | Follows Fig. 19's goal placement after text. FAST targets cannot enter the action expert's conditioning K/V. |
| Approximately 860M action expert, adaptive RMSNorm, 50 actions; pp. 4, 7 | One expert layer per VLM layer, adaptive RMSNorm, bidirectional action attention over detached VLM K/V | With the 34-layer Gemma 3 4B backbone, width 1024 and MLP width 4096 give 858,031,136 action-expert/projection/time parameters, approximately 860M. These dimensions are inferred choices, not checkpoint-compatible recovered dimensions. |
| Knowledge insulation and FAST CE; p. 3 | Joint masked FAST cross-entropy and flow-matching loss; flow gradients stop at the VLM/vision/state boundary | FAST codes are mapped to distinct added Gemma vocabulary tokens. The actual pretrained FAST processor is external. |
| Task, subtask, speed, quality, mistake, control mode; pp. 4–5 | `context.PromptContext`, `EpisodeMetadata`, strict scalar validation | `joint`/`ee` are text conditions, not coordinate converters. Speed uses nearest 500-step bins with explicit half-up ties. |
| Conditioning dropout; pp. 5–6 | Goals retained 25%; subtask dropped 30% only with retained goals; metadata dropped 15% as a group plus 5% per field; history/rear dropped 30% | Control mode remains present. Decisions are seeded by sample and epoch. Current observations survive history dropout. |
| Future image goals; p. 7 | Segment end with probability 25%, otherwise uniform frames up to four seconds ahead; optional pre-generated goal images | Uniform candidates stop at the episode boundary and may cross semantic segments. The generated-goal mixture probability is caller-selected because the paper does not specify it. Rear-view goals are excluded. |
| Training-time RTC, delays 0–12 steps; p. 7 | Clean action prefix, per-token flow time zero for that prefix, prefix excluded from flow loss; prefix re-clamped at inference | Flow-time sampling follows upstream OpenPI's beta schedule. The paper does not disclose this schedule. |
| Five flow steps, execute 15/25 of 50 actions, metadata CFG; p. 7 | Euler sampler and `policy.TorchPolicy`; metadata-only unconditional branch | CFG computes `v_cond + beta * (v_cond - v_uncond)` using separate forward passes, rather than Fig. 19's optimized attention tree. |
| Runtime metadata; p. 7 | `runtime_metadata(task_episode_lengths)` uses the 15th-percentile duration, quality 5, mistake false | Linear percentile interpolation and half-up duration bins are explicit conventions. Durations must come from the requested task. |
| Async language/goals/action inference, goal refresh on intent change or after 4 seconds; Algorithm 1, p. 7 | `runtime.Pi07Runtime`, coaching, episode reset, stale-result rejection, timestep-aligned action chunks | Model callables are injected. The scheduler never dispatches hardware commands or replays an expired action. |
| High-level semantic policy; p. 4 | `high_level.HighLevelModel`: observation-conditioned text CE and EOS-aware generation using the VLM/state modules | Requires coaching/subtask training data; `policy.TorchHighLevelPolicy` provides the runtime adapter. Greedy decoding and prompt wording are implementation choices. |
| BAGEL world model; pp. 5, 22–23 | `world_model.BagelMultiviewWorldModel`: native multi-view BAGEL flow training and joint three-view generation | Native adapter with explicit CPU contract tests; official BAGEL CUDA execution and trained weights remain unverified/external. |

The memory architecture also draws on [MEM](https://arxiv.org/html/2603.03596v1), especially its short visual history and longer language history. The spatial/temporal fusion used here is an explicit interpretation. RTC follows [Training-Time Action Conditioning](https://arxiv.org/html/2512.05964v1): keep prefix actions clean and supervise the postfix. This implementation uses the reversed flow-time convention, with clean data at `t=0` and noise at `t=1`, so clean-prefix time is zero.

## Isolated Windows setup and offline checks

Run these PowerShell commands from the repository root. Use a dedicated `.venv` for this path, separate from any legacy JAX/LeRobot environment. Python 3.12.4 was used for validation.

```powershell
uv venv .venv --python 3.12.4
uv pip install --python .venv/Scripts/python.exe torch==2.7.1 --index-url https://download.pytorch.org/whl/cpu
uv pip install --python .venv/Scripts/python.exe -r requirements-pi07.txt
$env:PYTHONPATH = (Join-Path (Get-Location) 'src')
$env:OMP_NUM_THREADS = '2'
$env:MKL_NUM_THREADS = '2'

.venv/Scripts/python.exe -m pytest tests/pi07 -q -p no:cacheprovider
.venv/Scripts/python.exe -m openpi.pi07.train --smoke --output tmp/pi07-smoke --steps 2 --device cpu
Get-Content tmp/pi07-smoke/run.json
```

Dependency installation needs package access; the tests and smoke run need no network, pretrained downloads, GPU, robot, or credentials. A compatible CUDA-enabled PyTorch installation is needed for subsequent `--device cuda` runs. The legacy installation instructions and GPU estimates elsewhere in the repository do not establish resource requirements for this implementation.

The smoke run trains a small randomly initialized Gemma 3 model with synthetic images, actions, text IDs, and action IDs. It writes `checkpoint.pt` and `run.json`, samples a `[2,50,3]` action tensor, and checks exact sample equality after checkpoint reload. Synthetic action IDs test the CE plumbing; they do not validate a trained FAST codec or robotic behavior.

Resume adds optimizer steps rather than specifying a total step count:

```powershell
.venv/Scripts/python.exe -m openpi.pi07.train --smoke --output tmp/pi07-smoke --resume tmp/pi07-smoke/checkpoint.pt --steps 2 --device cpu
```

Use a fresh output directory for a fresh run. Format-2 checkpoints include model configuration, optimizer state, step, RNG state, and exact values/dtypes of buffers that Hugging Face omits from its state dictionary, including rotary frequencies and embedding scales. Earlier checkpoint formats are rejected. Resume fingerprints include dataset contents, the tokenizer's complete encoding/normalization rules, and local FAST processor contents (including custom code/weights); the checked sampling, dtype, and processor settings must also match. Exact split-versus-uninterrupted updates are tested on CPU; GPU reproducibility is not established.

## Real local training inputs

Supply a local Gemma 3 **4B multimodal** checkpoint, its tokenizer, a pretrained FAST processor or matching cached FAST labels, and normalized robot episodes. The CLI sets `local_files_only=True`; missing assets cause an error rather than an implicit model download or tiny-model substitution.

Each NPZ contains one complete episode. Loading uses `allow_pickle=False`; save strings as Unicode scalars/arrays, not Python object arrays.

| NPZ field | Shape/type | Meaning |
| --- | --- | --- |
| `images` | `[N,V,H,W,3]`, uint8 or float in `[0,1]` | RGB, up to four ordered cameras. |
| `states` | `[N,S]`, finite real | Normalized state in a consistent coordinate layout. |
| `actions` | `[N,A]`, finite real | Normalized joint/EE actions aligned to observations. |
| `task`, `control_mode` | Unicode scalar | Overall task; control mode is exactly `joint` or `ee`. |
| `fps` | Positive scalar | Frame/control sample rate; use actual episode rate. |
| `timestamps` | Optional `[N]` | Strictly increasing seconds, otherwise derived from `fps`. |
| `subtask` | Optional Unicode scalar or `[N]` | Ground-truth segment instruction. |
| `quality` | Optional integer scalar, 1–5 | Ground-truth episode quality. |
| `mistake` | Optional boolean scalar or `[N]` | Ground-truth segment mistake label; strings such as `"false"` are rejected. |
| `segment_end` | Optional integer `[N]` | Inclusive end index of each frame's contiguous annotated segment; defaults to episode end. |
| `camera_names` | Optional unique Unicode `[V]` | Defaults to `front`, `left_wrist`, `right_wrist`, `rear`, in that order. |
| `action_mask` | Optional boolean `[N,A]` | Available action coordinates; defaults to all valid. |
| `generated_goals` | Optional `[N,G,H,W,3]` | Externally generated RGB goals, at most three views. |
| `fast_token_ids` | Optional integer `[N,F]` | Cached **extended Gemma vocabulary IDs** for each exact sampled 50-step action chunk, including EOS. These are not raw FAST codebook indices. |
| `fast_mask` | Optional boolean `[N,F]` | Valid cached tokens; defaults to all valid. |

Episode length supplies the training speed label. At the episode end, action chunks are zero-padded with false coordinate masks. `FASTCodec` repeats the final valid action when encoding the temporal padding; invalid coordinates are zeroed. Cached labels must match this convention, action normalization, chunk horizon, and the saved extended tokenizer. Do not create labels by independently quantizing scalar actions and calling them FAST.

Language memory is derived from earlier contiguous runs of `subtask` annotations. It excludes the current run and future labels, removes consecutive repetitions, and preserves repetitions separated by another instruction. `SamplingConfig.language_memory_limit` defaults to 64 prior instructions; set it to zero to disable this context. Run boundaries are precomputed, and segment annotation validation is linear in episode length.

The adapter loads episodes into memory. It does not reconstruct the paper's private robot/human/web mixture, annotators, RL experience collection, normalization statistics, or large-scale streaming pipeline. `--data-is-normalized` is an explicit caller assertion, not an automatic normalizer. Store the normalization statistics and coordinate mappings alongside your experiment.

For cached FAST IDs, use the extended tokenizer whose IDs generated those labels:

```powershell
.venv/Scripts/python.exe -m openpi.pi07.train `
  --backbone C:/models/gemma-3-4b-local `
  --tokenizer C:/models/pi07-extended-tokenizer `
  --data data/episode_0001.npz data/episode_0002.npz `
  --data-is-normalized --state-dim 32 --action-dim 32 `
  --device cuda --dtype bfloat16 --batch-size 1 --steps 100 --output checkpoints/pi07-run
```

Alternatively, supply a local FAST processor. Set the codebook size to the processor's verified value; `2048` below is an example configuration, not a paper-specified constant:

```powershell
$fastCodebookSize = 2048
.venv/Scripts/python.exe -m openpi.pi07.train `
  --backbone C:/models/gemma-3-4b-local `
  --fast-processor C:/models/fast-local --fast-codebook-size $fastCodebookSize `
  --data data/episode_0001.npz data/episode_0002.npz `
  --data-is-normalized --state-dim 32 --action-dim 32 `
  --device cuda --dtype bfloat16 --batch-size 1 --steps 100 --output checkpoints/pi07-fast-run
```

If that local processor requires reviewed custom Python code, add `--allow-processor-code`. Its action codes are mapped into new disjoint Gemma tokens; the extended tokenizer is saved under the output's `tokenizer` directory. Cached labels take precedence when present, so omit them if you intend to encode every chunk with the processor. Supply `--generated-goal-probability` explicitly when mixing the optional generated goal array into training.

AdamW, learning-rate/weight-decay defaults, gradient clipping, loss weights, and flow-time sampling are reference training choices. Full-scale training, convergence, GPU memory use, and published performance are unverified. The trainer accepts `--dtype float32` (default) or `--dtype bfloat16`, loading/converting model weights accordingly and retaining that choice in resume metadata. It has no AMP/scaler, distributed/sharded training, or reproduction of the paper's inference-speed optimization.

## Tensor and policy APIs

`EpisodeDataset.from_npz(paths, config=SamplingConfig(...), seed=0)` returns seeded NumPy examples; call `set_epoch(epoch)` for fresh augmentations. `collate_examples(examples, tokenizer, action_tokenizer=None, target_state_dim=None, target_action_dim=None, as_torch=False)` pads to the selected model dimensions and right-aligns history. It calls the FAST encoder on each original action tensor before coordinate padding. The text tokenizer maps a string to one-dimensional integer IDs.

The model batch contains:

```text
images[B,V,T,3,H,W]       image_mask[B,V,T]
states[B,T,S]            state_mask[B,T]
goal_images[B,G,3,H,W]   goal_mask[B,G]
input_ids[B,L]           text_mask[B,L]
actions[B,50,A]          action_mask[B,50,A]      # training
fast_token_ids[B,F]      fast_mask[B,F]          # training
```

Public floating RGB tensors are `[0,1]`; the VLA converts them to SigLIP `[-1,1]` internally. Masks are boolean. `Pi07(batch)` returns loss components; `Pi07.sample_actions(batch, previous_actions=..., delay=..., unconditional_batch=..., guidance_beta=...)` samples normalized actions. Training requires valid FAST labels; omitting the FAST processor and cached labels does not quietly switch to flow-only training.

The actual runtime bridge is `TorchPolicy`, and its call signature is `policy(PolicyRequest) -> ndarray[50,A]`. A typical setup after training is:

```python
from transformers import AutoTokenizer

from openpi.pi07.checkpoint import load_checkpoint
from openpi.pi07.context import runtime_metadata
from openpi.pi07.policy import TorchPolicy
from openpi.pi07.runtime import Pi07Runtime, RuntimeConfig

model, checkpoint = load_checkpoint("checkpoints/pi07-run/checkpoint.pt", device="cuda")
tokenizer = AutoTokenizer.from_pretrained("checkpoints/pi07-run/tokenizer", local_files_only=True)
policy = TorchPolicy(
    model,
    lambda text: tokenizer.encode(text, add_special_tokens=True),
    guidance_beta=1.7,
    num_steps=5,
)
runtime = Pi07Runtime(
    policy,
    task="fold the shirt",
    initial_subtask="fold the left sleeve",
    metadata=runtime_metadata([2000, 2300, 2600, 2100]),  # Replace with this task's recorded lengths.
    control_mode="joint",
    config=RuntimeConfig(execute_steps=25),
)
```

For each caller-owned control tick, call `runtime.step(observation, timestep=tick, timestamp=monotonic_seconds)`. An observation is `{"images": rgb_array[V,H,W,3], "state": normalized_state[S]}`; the state must already have the model's configured width. Camera ordering must remain consistent. Use the same monotonic timebase as the runtime clock. A return value of `None` means no valid action is available yet. The returned action is otherwise in model coordinates unless you supplied paired `action_normalizer`/`action_denormalizer` functions to `TorchPolicy`; both are required so RTC prefixes use the correct scale.

The caller owns sensor acquisition, control rate, action dispatch, limits, and behavior when no action is available. No hardware interface is provided. Call `runtime.coach("new subtask")` to suspend automatic language updates, `runtime.resume_autonomy()` to restore them, `runtime.reset(...)` between episodes, and `runtime.close()` at shutdown; the runtime also supports a `with` block.

Optional `high_level_policy` and `world_model` constructor arguments are callables receiving a `GenerationRequest`. The former returns a subtask string or `None`; the latter returns RGB goals `[G,H,W,3]`. Requests expose observation/history, task/context, language history, timestep, and timestamp. Intent is compared using normalized text by default, with an injectable `intent_key` for another definition. Late results from old intentions or episodes are rejected.

## High-level model and world-model boundary

`HighLevelModel.from_vla(vla, share_weights=False)` copies the VLM/state projection without constructing an action expert. With `share_weights=True`, high-level training also changes the original VLA; choose this deliberately. Its APIs are:

```python
from openpi.pi07.high_level import HighLevelModel

high_level = HighLevelModel.from_vla(model, share_weights=False)
# batch uses the image/state/text schema above. Prompt: task plus prior subtasks.
# target_ids: long [B,K], excludes BOS and includes EOS.
# target_mask: bool [B,K], a nonempty contiguous valid prefix in each row.
losses = high_level(batch, target_ids, target_mask)
losses["loss"].backward()
high_level.eval()
generated = high_level.generate(batch, max_new_tokens=64)
# Decode only generated.token_ids[row][generated.token_mask[row]].
# generated.finished[row] records whether EOS was reached.
```

For runtime integration, wrap the trained high-level model:

```python
from openpi.pi07.policy import TorchHighLevelPolicy

language_policy = TorchHighLevelPolicy(
    high_level,
    lambda text: tokenizer.encode(text, add_special_tokens=True),
    lambda ids: tokenizer.decode(ids, skip_special_tokens=True),
    max_new_tokens=64,
    require_eos=True,
)
# Pass high_level_policy=language_policy when constructing Pi07Runtime.
```

`TorchHighLevelPolicy(GenerationRequest)` returns a nonempty subtask string, omits the explicit current-subtask field/goals from its prompt, and retains issued-instruction history. History records issuance, not inferred completion. Truncation before EOS raises by default; `require_eos=False` explicitly accepts it. The high-level model still needs training data, an optimizer loop, and its own checkpoint workflow when independently copied.

The world-model adapter targets the [official BAGEL API at commit a2fa77dd8caeefc41e6607ae0ec17408d3f4ee9f](https://github.com/ByteDance-Seed/Bagel/blob/a2fa77dd8caeefc41e6607ae0ec17408d3f4ee9f/modeling/bagel/bagel.py). It receives already constructed pretrained modules; the normal VLA requirements file does not install BAGEL's separate CUDA/FlashAttention environment.

```python
from openpi.pi07.world_model import BagelGoalPolicy, BagelMultiviewWorldModel, WorldModelConfig

world = BagelMultiviewWorldModel(
    bagel, vae, bagel_tokenizer, special_token_ids,
    cache_factory=lambda: NaiveCache(bagel.config.llm_config.num_hidden_layers),
    config=WorldModelConfig(denoising_steps=25),
)
# bagel, vae, tokenizer, four special IDs, and NaiveCache come from the pinned
# official BAGEL installation and locally supplied pretrained weights.
world.train()
losses = world(current_images, segment_end_images, "Subtask: fold left sleeve.")
losses["loss"].backward()
world.eval()
goals = world.generate(current_images, "Subtask: fold left sleeve.")
goal_policy = BagelGoalPolicy(world)
# Pass world_model=goal_policy when constructing Pi07Runtime.
```

Each call represents one episode and exactly three ordered RGB cameras in `[3,3,H,W]` CHW layout, with uint8 or floating `[0,1]` inputs. The adapter resizes ViT observations to 448×336 and VAE observations/targets to 512×384 (width×height), constructs native `Bagel.forward` flow-training inputs, and generates the three views jointly. Each modality's views share a bidirectional attention block; there is no image collage or sequential per-view generation. Goals return as `[3,3,384,512]` float `[0,1]`.

For runtime use, pass `world_model=BagelGoalPolicy(world)` to `Pi07Runtime`. This adapter puts the world model in evaluation mode and reads `observation["images"]` in `[V,H,W,3]` layout: front, left wrist, right wrist, and an optional fourth rear camera. It ignores the rear camera; optional `camera_names` must confirm that ordering. It renders only subtask and episode metadata, calls joint generation, and returns float32 NumPy `[3,H,W,3]` goals. A missing subtask explicitly falls back to the overall task; missing metadata defaults to quality 5 and no mistake. State, history, existing goals, and control mode are not passed to BAGEL. `segment_end_example(episode_images, timestep, segment_end)` selects aligned current/target training images within one episode.

The adapter implements nested image/text guidance with separate native forward passes and defaults both strengths to one, because the paper omits their values. Figure 19 shows three branches: `(+text,+image)`, `(-text,+image)`, and `(+text,-image)`; the bottom branch retains image attention. The branch conditions match the figure and the pinned native implementation. The adapter also permits image guidance when text strength is one; the pinned native implementation gates its guidance application on text strength exceeding one. Norm rescaling is omitted. `WorldModelConfig.timestep_shift` is intentionally written to `bagel.timestep_shift` and `bagel.config.timestep_shift` at construction, so native training and sampling use the same configured shift. Training accepts explicit `drop_text`/`drop_images` flags; their sampling rates are caller choices because the paper does not disclose them.

CPU tests use clearly identified contract doubles for BAGEL packing/guidance; they do **not** verify execution with the real official CUDA model. Official model loading, real-world training, quantization, four-way H100 parallelism, SageAttention, and the reported 1.25-second goal generation remain unverified or external requirements.

## Validation and remaining limits

The offline suite checks history and goal boundaries, metadata/dropout probabilities, action masks, actual Gemma visual/backbone forward and backward passes, fixed-size temporal memory, attention/FAST leakage isolation, stopped flow gradients, RTC prefix preservation, CFG algebra, training/checkpoint continuation, high-level decoding, and asynchronous intent/reset/failure handling. The smoke command checks optimizer updates and exact checkpoint sample round-trips. Passing these checks validates implementation behavior at small scale; it does not reproduce the paper's task-success, generalization, or dexterity results.

The legacy `Pi07AlohaDataConfig` now preserves optional context across both repacking and ALOHA input conversion. Its dictionary wrapper and strict scalar handling are tested without legacy dependencies. The full legacy JAX/config/tokenizer integration was not executed in the isolated environment, and unrelated upstream model defaults remain unchanged.
